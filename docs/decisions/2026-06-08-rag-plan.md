## Contexte

La base de connaissances (RAG) alimente les agents IA (audit, copilot). Dette
connue dans `src/agents/knowledge/RAGService.ts` : l'embedding est un **placeholder**
(vecteur dérivé des char codes, pas sémantique), le schéma `knowledge_documents.embedding`
est en `vector(1536)`, et la page Connaissances affichait des documents **codés en dur**.

## Lots

### Lot A — Vue « Corpus Actif » réelle ✅ FAIT (commit à venir)
- `src/db/queries/knowledge.ts` : `listKnowledgeDocuments()` — regroupe par
  `document_name`, compte les chunks, date d'ingestion.
- `src/app/(dashboard)/connaissances/_components/knowledge-corpus.tsx` : liste
  réelle + recherche client + états vides.
- `page.tsx` : Server Component `async`, supprime les 3 faux documents.

### Lot B — Vrais embeddings Mistral + migration du schéma 🔜 EN COURS
- Remplacer `RAGService.generateEmbedding` (charCode) par un appel **`mistral-embed`**
  (SDK `@mistralai/mistralai`, déjà présent). Sortie validée, batch + erreurs gérées.
- `mistral-embed` produit des vecteurs **1024 dims** → migration du schéma
  `vector(1536)` → `vector(1024)` (Drizzle + snapshot). Les embeddings existants
  étant faux, ré-ingestion nécessaire (table vidée si besoin — vérifier le volume avant).
- Garde : pas de clé Mistral → dégradation propre, pas de crash.

### Lot C — Recherche sémantique réelle
- `searchContext` : requête `cosineDistance` sur les vrais vecteurs (pgvector),
  seuil de pertinence, top-k. Aujourd'hui la recherche s'appuie sur des vecteurs bidon.

### Lot D — Upload → ingestion + suppression
- Câbler `RAGDocumentUpload` → `ingestDocument` de bout en bout (le corpus se met
  à jour après upload).
- Ajouter la **suppression** d'un document (le bouton corbeille retiré de la vue
  réelle) — Server Action + query + révalidation.

### Lot E — Branchement RAG dans les agents + journalisation
- S'assurer que les agents d'audit consomment réellement le contexte RAG.
- Journaliser l'ingestion / l'usage de tokens (`audit_logs`).
