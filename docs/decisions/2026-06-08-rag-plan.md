## Contexte

La base de connaissances (RAG) alimente les agents IA (audit, copilot). Dette
connue dans `src/agents/knowledge/RAGService.ts` : l'embedding est un **placeholder**
(vecteur dérivé des char codes, pas sémantique), le schéma `knowledge_documents.embedding`
est en `vector(1536)`, et la page Connaissances affichait des documents **codés en dur**.

## Lots

### Lot A — Vue « Corpus Actif » réelle ✅ FAIT (commit à venir)
- `src/db/queries/knowledge.ts` : `listKnowledgeDocuments()` — regroupe par
  `document_name`, compte les chunks, date d'ingestion.
- `src/app/(dashboard)/connaissances/_components/knowledge-corpus.tsx` : liste
  réelle + recherche client + états vides.
- `page.tsx` : Server Component `async`, supprime les 3 faux documents.

### Lot B — Vrais embeddings Mistral + migration du schéma ✅ FAIT
- `RAGService.generateEmbedding` appelle désormais **`mistral-embed`** (1024 dims),
  sortie validée Zod. Si pas de clé Mistral → throw propre (ingest/search dégradent).
- Schéma `vector(1536)` → `vector(1024)` ; migration `drizzle/0005_rag_embedding_1024.sql`.
- **DB en mode `push`** (pas de journal `__drizzle_migrations`) → l'unique `ALTER` a
  été appliqué directement via psql (table `knowledge_documents` **vide** = 0 risque,
  pas de ré-ingestion). Snapshot Drizzle régénéré pour la parité.

### Lot C — Recherche sémantique réelle ✅ FAIT
- `searchContext` : `cosineDistance` sur les vrais vecteurs + **seuil de pertinence**
  (`RELEVANCE_THRESHOLD = 0.4`, paramétrable). Une requête sans voisin pertinent
  renvoie désormais un set **vide** au lieu du top-3 inutile — c'est ce signal que
  le CopilotAgent exploite pour « faible confiance / aucun voisin ».
- À ajuster empiriquement une fois un vrai corpus ingéré. Index vectoriel
  (HNSW/IVFFlat) = optimisation perf à prévoir si le corpus grossit (pas critique
  à 0 doc).

### Lot D — Upload → ingestion + suppression ✅ FAIT
- La chaîne upload→ingestion existait déjà (`RAGDocumentUpload` → `/api/knowledge/upload`
  → `ingestDocument`). Durcie : **auth** (était ouverte !), limite **10 Mo**, **PDF**
  branché (util `src/lib/utils/pdf-text.ts` via pdf2json), garde « 0 chunk » → 502
  explicite (clé Mistral manquante).
- **Suppression** : query `deleteKnowledgeDocument` + Server Action
  `supprimerDocumentAction` (auth + Zod + revalidate) + bouton corbeille (confirm +
  spinner + refresh) dans la vue corpus.

### Lot E — Journalisation (audit trail) + cleanup ✅ FAIT
- **Constat** : le RAG était **déjà branché** dans les agents (auditWorker, copilot,
  importWorker appellent tous `searchContext`). Avec les Lots B+D (vrais embeddings
  + corpus rempli), ils s'en servent désormais réellement.
- **Traçabilité** (le vrai trou — `audit_logs` n'était jamais écrit par les agents) :
  helper `writeAuditLog` (best-effort, ne casse jamais l'action) + journalisation de
  l'**ingestion** et de la **suppression** RAG, et de l'**audit** (`/api/agents/audit`).
- **Sécurité** : la route `/api/agents/audit` était **sans auth** → ajoutée + userId
  réel propagé au worker.
- **Cleanup** : `src/agents/audit-agent.ts` (doublon legacy SANS RAG, mort) supprimé.

#### Dette restante (hors lot E, notée)
- `auditWorker.ts` tourne encore sur **Anthropic** (`@anthropic-ai/sdk`, claude-3-5),

  (chantier séparé). La **journalisation des tokens** par appel sera branchée à ce
  moment-là (aujourd'hui on logge action + entités + métadonnées, pas les tokens).
- `RAGService` et `auditWorker` importent `@/db` directement (violation de frontière
