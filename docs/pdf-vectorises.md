# PDF d'étiquettes au texte vectorisé

**Établi le** : 2026-09-24 — **Périmètre** : tous les PDF du stockage de préproduction (`label-assets-preprod`, dossier `ÉTIQUETTES 2026-09/`, reflet de l'archive du Graphisme)  
**Statut** : à traiter plus tard. Rien n'est modifié dans l'application.

## Le problème en deux phrases

Dans ces PDF, le texte a été converti en tracés à l'export d'Illustrator (« vectoriser le texte ») : le fichier ne contient plus ni police ni lettre, seulement des dessins. L'étiquette est parfaite à l'impression, mais GaïaLabel ne peut rien y lire : tous les contrôles qui lisent le texte du BAT (liste d'ingrédients, mentions, tailles de caractères…) répondent « à vérifier ».

**Produits touchés** (sur 394 produits qui ont un BAT) : **62 dont tous les BAT sont vectorisés** — aucun contrôle de texte possible — et **23 dont une face seulement l'est** — contrôles partiels.

Années de création des PDF vectorisés : 2024 : 209, 2025 : 38, 2026 : 19. Le gros vient d'un lot d'exports de 2024 (versions V5, Illustrator 28.2).

## Solutions

1. **Les `.ai`** : un fichier Illustrator garde le texte (vérifié : les 38 anciens `.ai` retrouvés pour ces produits ont tous texte et polices). Ouro a les `.ai` : ré-exporter un PDF **sans vectoriser le texte**. Déposer le `.ai` lui-même est aussi possible : il se lit avec les mêmes outils qu'un PDF, mais l'audit ne prend aujourd'hui que les PDF — ce serait à brancher.
2. **JDG / le Graphisme** renvoie des PDF exportés avec le texte conservé.
3. En dernier recours, lire le texte par OCR (voir `docs/journal-controles.md`, §5).

**Pour vérifier un PDF** : l'ouvrir dans Acrobat et essayer de surligner un mot. Si on ne peut pas, il est vectorisé.
